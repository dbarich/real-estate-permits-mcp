# Commit Proposal — v0.2.1-alpha version-control hygiene

**Date:** 2026-05-31
**Proposed by:** Cowork session (agent proposes; human ratifies)
**Status:** PENDING RATIFICATION (commit/push from host terminal)
**Release:** v0.2.1-alpha (post-release housekeeping sub-version; no behavior change)

## Why
Version control had not been a focus. `pyproject.toml` was stranded at
`0.1.0-alpha` while the repo was tagged `v0.2.0-alpha`, there was no CHANGELOG,
no programmatic version on the server, and the recurring sandbox `.git` lock
problem was undocumented. This is a "clean the yard while waiting on tester
feedback" pass — purely hygiene, no server or tool behavior changes.

## Proposed commit message
```
v0.2.1-alpha: version-control hygiene (CHANGELOG, version sync, unlock script, roadmap refresh)
```

| `pyproject.toml` | `version` 0.1.0-alpha → 0.2.1-alpha | Sync package metadata to the release line; was stale by two versions |

## Alternatives considered
- **Move the `v0.2.0-alpha` tag to include this hygiene work** vs. cut a new
  `v0.2.1-alpha`. Rejected the tag move: force-moving a published tag rewrites a
  release others may have pulled, and this work is genuinely post-release
  housekeeping, not part of the hardening milestone. A fresh sub-version is the
  honest record.
- **Single source of version truth (pyproject dynamic / read `__version__`)** vs.
  two hardcoded strings kept in sync. Chose two synced strings: dynamic versioning
  requires the package to be importable at build time and adds setuptools config
  this alpha doesn't need. Documented the sync requirement in CLAUDE.md instead.
- **Truly fix the sandbox `.git` lock root cause** vs. ship a documented unlock
  script. The root cause is the mount's `unlink` permission model, which we can't
  change from here; the script + CLAUDE.md ritual is the pragmatic fix. Flagged
  upstream feedback as a separate, optional path.
- **Commit from Cowork using the `GIT_INDEX_FILE` plumbing workaround** vs. commit
  from the host terminal. The plumbing path was attempted and failed (stale
  `HEAD.lock`/`main.lock` the sandbox can't remove), confirming the
  propose-then-ratify split as the reliable model rather than a workaround to keep
  chasing.

## Not included (deliberate)
- `skills/surgical-build/` — stays local (now gitignored).
- `CLAUDE.md` — gitignored local memory; updated this session but not committed by design.
- Tag move — `v0.2.0-alpha` tag stays put; this is a new `v0.2.1-alpha` sub-version, not a re-tag.
